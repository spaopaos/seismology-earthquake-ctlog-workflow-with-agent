# 拾取环节故障排查

排查顺序：本表 → `references/EQNET_FACTS.md` → `knowledge/repos/EQNet@af94a08`（只读）→ `knowledge/papers/` → 报告用户。

| 症状 | 先查 | 典型原因 |
|---|---|---|
| 输出 CSV 数远少于输入（COLLISION 断言触发） | `--subdir_level` 与 data_list 路径布局 | 输出文件名塌缩，旧结果被覆盖（F20）。调整布局或 subdir_level，重跑受影响部分 |
| HN 组拾取数异常低/波形形态像被滤波 | 是否绕过了 shim（直调原版 `predict.py`） | F1（HN 积分）或 F3（默认高通 1.0）。只允许经 `scripts/eqnet_pick.py` 调用 |
| 极性几乎全缺失或方向看起来反了 | 分量顺序 | F6/F12：数组必须是 E,N,Z；归档是 Z,N,E。检查 shim 的重排与 verify 脚本结果 |
| 密集序列日拾取数平台化（不再随事件增多） | K 上限 | F18：每 30 s 每震相 ≤10 个。属模型固有限制，记录并在报告中说明 |
| 同一数据两次运行拾取差 ~7% | 后端/设备 | F23：TF32 与后端差异，属正常范围；判据是计数量级 |
| 显存溢出（整日输入） | 单组日显存实测 | 转分块降级：最长可行块 + ≥60 s 边缘裁弃，块长记入 contract；先做单组日整日 vs 分块对比 |
| 拾取时刻整体偏移一个固定量 | begin_time 精度 / 采样率 | F8 毫秒截断最多 0.1 采样点；更大偏移查采样率是否非 100 Hz 被插值（F4，应已被门槛拦截） |
| `data_list` 行数 ≠ 预期组日数 | build_data_list 的筛选 | manifest 状态过滤（只 READY/PARTIAL_DAY）；查跳过清单 |

## 禁止的"修复"

- 不修改用户全局安装的 EQNet；不偷改通道名绕过 HN 判断；
- 不为通过计数断言而降低阈值或重跑到"看起来对"；
- 拾取异常时不改 `--min_prob` 试凑（改动须记录依据并重回小批验证）。
