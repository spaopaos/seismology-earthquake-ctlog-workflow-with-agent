Encode cross-region decision rules for the insar stage (atmospheric/ionospheric correction, detectability thresholds)

The workflow deploys across regions: region-dependent physics is never
inherited from a previous region. New decision table in the skill
(agent decides from evidence or escalates to the user):

- tropospheric correction: decided AFTER first maps from three evidence
  checks (expected signal scale vs atmospheric noise; stripe morphology;
  asc/desc consistency); applied via GACOS or PyAPS/ERA5 when triggered,
  raw and corrected maps both delivered; escalation when evidence is
  ambiguous, credentials are missing, or the event is significant
- ionospheric correction: band/latitude rules (C-band off; L-band e.g.
  the NISAR path, or high-latitude regions -> on, user confirms)
- ml_min detectability: per-region checkpoint with rationale (climate/
  vegetation/depth distribution), user confirms on first use
- look-direction heuristic verification against ASF flightDirection on
  first use per region; coherence threshold adjustment rules; seasonal
  interpretation of quality scores

binding/insar.md, AGENTS.md and the example-config rationale carry the
same policy; knowledge manifest regenerated, tests pass.
