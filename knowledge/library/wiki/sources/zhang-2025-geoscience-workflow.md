# Streamlining geoscience data analysis with an LLM-driven workflow

**Citation:** Jiyin Zhang; Cory Clairmont; Xiang Que; Wenjia Li; Weilin Chen; Chenhao Li; Xiaogang Ma (2025). Applied Computing and Geosciences 25, 100218. DOI: 10.1016/j.acags.2024.100218.

**Version note:** Journal volume year 2025; the DOI contains 2024.

## Research problem

The study makes mineralogical data retrieval and analysis accessible through natural language. It connects LLM interpretation to OpenMindat APIs and predefined visualization functions, reducing the amount of programming needed by users.

## Architecture

A supervisor routes work to four specialized action agents: Geomaterial Collector, Locality Collector, Network Plotter, and Heatmap Plotter. The implementation uses GPT-4o with role descriptions, tool instructions, and examples. Structured tool arguments are validated with Pydantic before accessing data endpoints.

Each action returns results to the supervisor, which chooses the next step or terminates the workflow. Analysis outputs are generated by the actual data-processing and plotting tools. Logs expose the sequence of decisions and intermediate results.

## Evidence

The paper demonstrates mineral co-occurrence networks and locality distribution heatmaps. These examples support feasibility within the implemented data endpoints and visualization tasks. They do not provide a comprehensive benchmark of general geoscience reasoning.

## Scope and limitations

The future-work section explicitly proposes broader performance evaluation using accuracy, recall, and pass rates. Those planned measurements must not be described as completed results. Extensions to additional datasets, agents, and open models remain separate from the demonstrated workflow.

Repeatability of a tool call presumes consistent arguments, software, and underlying data. A live data API may change, and different LLM runs may choose different arguments. The paper's reproducibility argument therefore does not justify treating all agent sessions as deterministic.

## Relevance to this collection

The supervisor-plus-tools pattern offers a practical comparison with [autoba](../entities/autoba.md) and [specfem-mcp](../entities/specfem-mcp.md). It supports the idea of exposing bounded scientific operations with clear input contracts and inspectable results.
