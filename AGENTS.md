# Agent entry point

This is a portable regional seismology workflow. Start here without relying on previous conversations, the developer's filesystem, or installed software with a familiar name.

1. Read README.md, docs/DEPLOYMENT.md, docs/SUPPORTED_INPUTS.md and docs/WIKI_INTEGRATION.md. The included knowledge/library is an exported, fixed snapshot of the maintained LLM Wiki. It can be queried with `seisflow.py knowledge`; the desktop app, its model-provider setup and its compatibility runtime are optional authoring tools, not execution dependencies. Run `seisflow.py doctor` using an explicit runtime mapping. Reuse an existing suitable runtime or the supplied snapshots. Never install, upgrade, or create environments without the user's authorization. The deployment script itself is an explicit user-selected operation.
2. Initialize a NEW run directory with `seisflow.py init --workdir <run>`. Inspect the current raw waveforms, response information and station metadata. Resolve genuinely missing information; retain choices already made by the user. Record decisions in pipeline.json and processing notes. Do not copy the developer's region or dates.
3. Read `skills/seismic-preprocess/SKILL.md` and `docs/ARCHIVE_INTERFACE.md`. Write data-specific preprocessing/adaptation code in `<run>/processing/`. Raw input format and directory layout are intentionally open. Preserve code, input mapping, actual parameters, response/orientation evidence and QC. A velocity model is not a prerequisite for preprocessing or picking.
4. Publish the standardized archive using the fixed preprocessing validator. Once the archive exists, all later stages use maintained converters and runners, with region inputs and configuration. Do not recreate fixed-format converters, edit pinned upstream code, or invent missing output fields.
5. Run stages through `seisflow.py --runtime <mapping> run --config <run>/pipeline.json --stage <stage>`. Read the corresponding skill and its knowledge/bindings page before each stage. The stage route separates method background, historical manuals, current implementation and project policy. Use `knowledge read/source` with the run directory to record access, and `knowledge cite` for a parameter explanation. Do not treat a Wiki statement as a default for a different software version. The `all` option starts at archive validation; it cannot infer unknown raw layouts without your preprocessing work.
6. GaMMA: explain DBSCAN eps, recommend 10 seconds, calculate the pinned helper's estimate, and consume the user's selection. Missing selection is a decision checkpoint; do not select it silently. First HypoDD: derive/check a current Vp/Vs, run the documented DAMP trials, and use spatial evidence; CND alone is not a gate. MESS: medium templates only, one scan/association, independent CC 0.4/0.6/0.8 products. Then run post_detection_relocation: joint lite CC+CT (IDAT=3), with the MESS-native dt.cc plus the first-round medium-tier ph2dt dt.ct reused verbatim (no re-picking, no new ph2dt run), separately select DAMP for each CC tier using the same spatial rule, and publish exactly THREE final catalogs. Never expand them into nine catalogs or silently fall back to one time-data type.
7. Inspect actual QC. A successful process or contract is not a scientific accuracy claim. An unavailable/empty tier or missing metadata must be explained. Keep valid partial products and state what can run next. Do not lower thresholds merely to produce a nonempty result.
8. Report products, actual parameters and sources, runtime/cost, checks performed, exclusions and limitations. Use run_state.json and logs to hand over to the next agent.

The maintained skills are in `skills/`; an agent can read them directly. Automatic skill discovery is optional and agent-specific. This package needs ordinary local file/command access, not an agent framework or mandatory MCP server.

Defaults in configs/pipeline.example.json are initial working settings, not fitted regional optima. Confirm analysis bounds, datum and applicability. A changed model, station list or parameter experiment gets a new run directory. Never alter a saved validation/hash file to bypass a rejection.

The driver records knowledge.lock.json, per-stage available context and a manifest identity in run_state.json. Automatically provided context is not a claim that you read it. When using a critical statement, check the linked PDF page/code and record the actual parameter reason. Keep source PDFs immutable. Do not edit a release Wiki during analysis or assign new Wiki provenance to an old completed run; maintain the live Wiki separately and export a new release.
